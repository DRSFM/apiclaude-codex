## 实现与运行边界

- 保留原版 Desktop/CLI，新增 `codex_delegate.py` 与 `codex_delegate_runtime.py`，
  由独立账号的官方 app-server 执行。提供查询账号、派发、查询任务、等待、追问和中断。
- 主任务归属使用官方 MCP `_meta.threadId`；任务绑定目标账号/模型。
  稳定 request_id 跨 MCP 实例去重，每账号同时只允许一个委派任务。
  停止或断开保留官方历史，需显式继续；不自动切号、换模型或重复任务。
- 原生旧格式历史走官方 `thread/fork`；新版分页历史通过官方 `thread/read`
  传递支持的可见消息和工具结果，返回 `official_visible_history` 标记。
  后者不含隐藏推理，不保证图片、未支持项或完整内部状态等价；超过 1 MiB 显式失败，不截断。
- 两个已注册入口的工作目录限制为 `D:/codex项目/apiclaude-codex` 和
  `E:/新版codex工作区/多账户使用调研学习`，目标固定 account-b，默认模型 gpt-5.6-sol。
  已安装设置为官方 workspace-write，不继承父窗口实时权限；官方沙箱仍决定具体写权限。
  apps/plugins 暂不接入，其他 MCP 各自权限仍适用，不声称连接器或原生子代理面板完全一致。
- 委派端不会替用户批准交互请求。`--trust-tools` 是单独、显式的安装选项，
  只设置本机委派工具 spawn/send_message/interrupt 的官方 approval_mode，
  已经用户明确同意后在上述两个来源启用；不设置其他工具的批准策略。
- 凭据始终由官方账号目录和客户端维护；没有导出、复制、重放真实凭据或主动强刷。

## 使用与后续边界

重新加载 MCP 或在对应 profile 新开任务后，可以直接要求主模型把独立子任务交给 B。
两个项目的 AGENTS 已允许在用户任务范围内主动委派；何时值得委派仍由主模型判断，
不是每条消息都额外调用 B。可切换目标账号实际支持的模型；本轮真实验收覆盖 Sol，
没有额外验证 Luna。模型额度、服务可用性和完整原生 UI 一致性不在此成功结论内。

研究工作区的 `已启用-委派工具信任.toml` 保存精确授权补丁；如需撤销，
重新执行安装命令但不加 `--trust-tools`，然后重载 MCP。已完成任务和官方历史保留。
