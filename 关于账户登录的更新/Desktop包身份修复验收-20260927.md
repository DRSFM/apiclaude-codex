# Desktop 程序包身份修复验收

日期：2026-09-27（Asia/Hong_Kong）。范围：Windows Desktop 启动兼容修复。

## 原因与实现

08:56:36 的 B 账号启动日志先记录 `bootstrap-import-main` 失败，再记录更新器错误“该进程没有程序包标识符”。安装包 `OpenAI.Codex_26.924.2738.0_x64__2p2nqsd0c76g0` 状态正常。暂停执行的直接 EXE 启动探针返回 Windows 15700；正常主窗口查询包身份成功。

`start_detached_process` 对 `ChatGPT.exe` 且存在相邻 AppxManifest 的路径转入包启动助手，其他命令和非打包覆盖路径维持原实现。助手通过 PowerShell 7 的 `Invoke-CommandInDesktopPackage` 启动，使用注册包路径精确匹配，并让助手及其子进程保持包身份。

系统激活接口实测不会继承调用方环境，故不能直接用于账号启动。父进程持有双向管道；助手以 `PROCESS_DUP_HANDLE` 复制指定管道端点，接收 JSON 格式的已清理环境、参数与工作目录，再启动 Desktop 并验证其包身份与助手相同。未使用 pickle、临时凭据文件、命令行凭据或全局环境变量。父进程和助手均有限时等待，结束后关闭端点；身份失败只终止助手刚创建的进程，激活失败不回退到无身份启动。

微软将该接口定位为包内调试/诊断工具，承诺包身份而不保证所有 App 设置的行为等同正常激活。本修复针对官方 FullTrust Desktop 实测，不改安装包、系统注册或权限；升级后应保留原生环境探针和实际窗口启动验收。来源：[Microsoft Learn](https://learn.microsoft.com/en-us/powershell/module/appx/invoke-commandindesktoppackage?view=windowsserver2025-ps)。
