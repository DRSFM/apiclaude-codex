# 额度查询与保底验收（2026-09-21）

按用户明确选择：保留 10%；触线时让正在运行的任务完成，停止新派发和追问；
查询失败先暂停。已实现并部署，新 MCP 工具名为 `get_usage`。

## 行为

- 通过 B 官方客户端调用 `account/rateLimits/read`，查询本身不生成模型回复，
  不强制刷新/登录，不调用任何重置额度或额外购买接口。
- 返回账号、查询时间、各计费桶的窗口时长/已用/剩余/重置时间，以及
  `guard.allowNewCalls`、拒绝原因和 `activeTaskPolicy=finish`。
- `spawn`、已完成任务的 `send_message` 续聊，以及运行中的实时追加指令，
  均由控制器用新查询做检查；只依靠 Skill 提醒不能绕过此检查。
- 任一返回的 300 分钟或 10080 分钟窗口剩余 ≤10% 即暂停；多桶保守检查，
  不将桶相加，也不猜测某个桶只适用于哪个模型。官方禁止普通用量或开支限制同样暂停。
- 额度/窗口数据不全、普通用量许可未知、异常数值、已过去且未滚动的重置数据、
  网络或认证查询失败均暂停；仅达到重置时间不等于恢复，须重新取得健康的官方读数。
- 被拒绝的首次派发保存 `quota_blocked` 记录，不创建官方线程或模型 turn；
  恢复后可用原 request_id 和原参数显式重试，旧归档保留。
- 被拒绝的追问返回 `accepted=false` 和原 `taskStatus`，保持原会话、答案和实际运行状态；
  活动任务继续完成，`wait` 收结果，`interrupt` 始终可手动调用。恢复后继续同一线程。
- 不自动重试、换账号、买额度或中断已运行任务。这是新调用准入检查，不是精确的
  token/额度硬上限；当前任务及账号的其他活动可能消耗部分保底。
