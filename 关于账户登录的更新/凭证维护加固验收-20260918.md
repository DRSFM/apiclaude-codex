# 凭证维护加固验收（2026-09-18）

用户确认的范围：借鉴 Cockpit 方法，导入后由 apicodex 启动的官方客户端维护；不与 Cockpit 持续同步。

## 实际行为

- CLI 与 Desktop 沿用同一个具名账号目录中的官方加密凭证，不增加凭证副本或后台刷新器。
- 每次检查重新读取官方存储；同一账号的包装器检查串行执行，管理入口的状态检查也与导入、退出登录互斥。
- 已有活动会话时，`account login` 只检查缓存；`account status --refresh` 提示先关闭会话，普通 `status` 可用。
- 官方返回永久认证错误时，如果期间密文版本发生变化，重新读取一次，不再额外请求刷新。仍失败才提示重新登录；临时服务错误保留凭证。
- `import --update` 读取当前加密存储，拒绝不同账户/用户、移除已有刷新令牌、旧凭证或顺序不明确的更新。
- 相同令牌不改写密文或刷新时间。顺序依据刷新时间或令牌签发时间，并检查时间/到期回退；不用文件修改时间，也不单凭更晚到期就接受。
- 写入前检查密文和密钥是否发生变化。失败回滚只恢复本事务仍持有的版本；期间官方写入的新版本会被保留，并报告冲突。

## 边界

- 本轮未用真实账户主动刷新、重新登录或调用模型；模拟测试不能证明真实登录永不失效。
- 包装器锁不能约束绕过启动器的外部进程，也不消除外部写入与本地替换之间的全部竞态；导入仍要求关闭所管理的活动会话。
- 本地时间及 JWT 声明用于保守排序，不是服务器认证；缺少顺序信息时拒绝覆盖，可走官方登录。
- `--dry-run` 仍是导出预览，不读取目标凭据，不预先证明更新可接受。
- `account sync` 仍用于共享资源；账号凭证通过官方存储维护，无需新增日常同步命令。
