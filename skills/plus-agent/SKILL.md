# Plus 账号子代理

使用已配置的 `apicodex_delegate` MCP，在当前对话的项目目录中调用 B。
主模型继续负责规划、整合和最终验收；本 Skill 授权为用户当前任务作适当委派，
不要求每个项目另外添加 AGENTS.md。用户只调用 Skill、未提供任务时，先询问要做什么。

1. 调用 `list_accounts`，核对 B（通常别名 `account-b`）、默认模型、workspacePolicy
   和沙箱。沿用用户指定的可用模型，否则用返回的默认模型；不自动切换账号。
   派发前用 `get_usage` 查询额度；用户只要查额度时，到此返回结果，不启动子任务。
   显示各窗口的剩余百分比和本地时区重置时间，不把多个计费桶相加。
   任一返回的 5h/7d 窗口剩余 ≤10%、官方限制使用或额度不可确认时，
   `guard.allowNewCalls=false`，暂停新派发和追问并说明原因。
2. 选取能独立完成、范围明确的子任务。调用 `spawn` 时，**始终显式传当前项目的
   绝对 cwd**，不要用 Skill 所在目录或控制器目录。`workspacePolicy=any` 表示
   无需逐个登记项目，不代表可以修改用户任务之外的文件；原沙箱和授权仍适用。
3. **始终显式传 `context=none`**。`message` 通常只需几句话：任务、必要背景、
   文件位置、允许修改的范围及验收条件。不要复制父对话、聊天 JSON、完整工具日志，
   也不要读取或 fork 父会话来补背景；缺少信息时由主模型补充具体事实或必要文件片段。
   可附 `codex://threads/<id>` 作为会话定位引用，不展开为完整历史，也不假设 B 能读取
   另一账号的线程。链接不能替代执行必需的事实；B 缺什么再定向补什么。
   使用稳定的 `request_id`，同一请求重试保留原参数。新版的旧参数 `auto` 也不继承历史，
   但显式 `none` 还能避免尚未重载的旧服务自动附带历史。
4. 用 `wait` 等待；仍在运行就继续等待，不重新派发。同一 B 同时只有一个任务。
   用 `send_message` 简短补充或继续同一任务，用 `interrupt` 停止。
   旧任务若 context.mode 为 official_fork 或 official_visible_history，不再追问；
   等已有执行结束后，用新 request_id 和简短任务说明新建，原结果和记录保留。
   控制器对派发、续聊和追加指令都重新查额度。返回 `quota_blocked` 表示这次调用
   未被接受；保留原任务和已有结果，不把它报成完成，也不立即反复重试。
   额度触线时让已运行的任务完成，继续 `wait` 收结果；不要仅因额度不足主动中断。
   稍后重新查询确认 `guard.allowNewCalls=true` 才继续；仅到重置时间不等于额度恢复。
   明确因额度拦截且未创建线程的派发，可在恢复后用原 request_id 和原参数重试；
   无父历史的已有线程用 `send_message` 接续。不承诺当前任务结束时一定还剩 10%。
5. 核查结果及相关文件或测试，再向用户报告账号/模型、结论和必要的结果路径。
   控制器会在当前项目的 `子代理任务/` 留存任务、可见过程、结果与索引，无需另建一套。

调用前简短说明“交给 B 执行，我负责验收”；等待较久时给出有意义的进展。
界面记录是 MCP 的 spawn/wait 等调用，不声称出现在原生子代理面板。
B 新任务只接收任务说明，并按需读取项目文件；同一 B 任务的后续追问保留其自身上下文。

工具不可用时说明当前 profile 尚未加载委派 MCP，建议重载或检查注册；不要用
shell 另起 B 绕过控制器。遇到审批、额度、登录或模型错误时保留记录并报告，
不自行修改信任/权限/登录状态，也不在结果不确定时重复任务。子代理不得递归委派。
